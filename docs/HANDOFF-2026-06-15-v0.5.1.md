# 引き継ぎメモ — v0.5.1 (2026-06-15)

## 概要

今回の主題は Hyperliquid 上の対象銘柄に対する不特定多数 TWAP の観測。

QuickNode / HyperCore node provider があれば全 TWAP stream の履歴 scan も候補になるが、今回は「blockchain 特有の free の情報」から取得する方針に寄せ、Hyperliquid official info endpoint だけで動くサンプル推定を実装した。

## 実装

- `scripts/hl_public_twap_monitor.py`
  - `--user-sample`
  - `--discover-users recent-trades`
  - `--sample-rank-by target_volume|target_fills|all_volume|all_fills|account_value|input_order`
  - `--sample-report-mode twap-notional|twap-share|all`

## デフォルト比較

要求された比較 window:

- current: 直近 1 時間
- past: 12 時間前を終点にした 1 時間

既存の TWAP 総額比較は `--sample-report-mode twap-notional` として残した。

## 追加した説明力のある比較

1. TWAP share
   - 分子: selected users の対象銘柄 TWAP notional。
   - 分母: selected users の対象銘柄全約定 notional。
   - 意味: 監視対象ウォレット群の activity のうち TWAP がどれだけ支配的か。

2. TWAP notional imbalance
   - `(BUY_TWAP_NOTIONAL - SELL_TWAP_NOTIONAL) / (BUY_TWAP_NOTIONAL + SELL_TWAP_NOTIONAL)`
   - BUY 側に寄ると正、SELL 側に寄ると負。
   - SELL 側はヘッジやポジション解消が混在するので補助指標扱い。

## 実行例

```bash
.venv/bin/python scripts/hl_public_twap_monitor.py \
  --coin HYPE \
  --user-sample \
  --discover-users recent-trades \
  --sample-rank-by target_volume \
  --sample-top-n 50 \
  --sample-concurrency 1 \
  --sample-report-mode all
```

## 検証

```bash
.venv/bin/python -m py_compile scripts/hl_public_twap_monitor.py
.venv/bin/ruff check scripts/hl_public_twap_monitor.py
```

さらに公式 free API で小サンプル実行し、`twap-share` / `all` / default の出力切り替えを確認済み。

## 注意

- `recentTrades` discovery の観測が短いと候補ユーザーが偏る。実運用では `--discover-seconds` と `--discover-max-trades` を調整する。
- 429 を避けるため、まず `--sample-concurrency 1` を推奨。
- current と past は同じ selected users の比較。12 時間前当時の出来高上位を別途選ぶ比較ではない。
