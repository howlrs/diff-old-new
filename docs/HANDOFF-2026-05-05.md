## 3. 次セッションの着手順 (PR-C2 → PR-C3 → PR-C4)

### Step PR-C2: symbol allowlist + size cap (優先度高)

**目的**: production 投入時の誤配置防止. ETH 以外の符号で algo が誤発注しても server が拒否する強固な安全網.

`executor-server` に CLI flag 追加:
- `--mainnet-allow-symbols ETH,BTC` (カンマ区切り, default: 空 = 全許可)
- `--mainnet-max-notional-usd 20` (default: 無制限)

実装:
- `start_exec` route handler に middleware 的に gate を入れる
  - request.symbol が allowlist に無ければ 400 Bad Request
  - request.size * px > max_notional_usd なら 400 Bad Request
- `BatchSender` enqueue 直前にも同じ gate を入れる (defense in depth)
- mock mode では gate スキップ (CI 既存テストへの影響回避)

PR-C1 で `MetaCache` 完成済なので, allowlist 検証で `meta.resolve(&symbol)` を呼んで symbol の実在性確認も可能.

### Step PR-C3: baseline-diff guard

**目的**: 起動時に master EOA の HYPE / xyz:META / xyz:GOOGL ポジションを snapshot. 周期的 (例: 1 分毎) に再取得して **既存ポジ szi が変動 → 自動 emergency_stop**.

実装:
- `ServerState::baseline: Arc<Mutex<HashMap<Symbol, Decimal>>>` 起動時に `fetch_account_state` で populate
- tokio task で 60s 毎に再 fetch → diff
- 違反検知時: `emergency_stop` route を内部呼び出し + tracing::error + alert (slack/log)

⚠ Gemini deep review で「片肺リスク」(複数注文の一部失敗) が SUGGESTION として挙がっていた点と関連. PR-C2 の gate と PR-C3 の guard で 2 段防御.

### Step PR-C4: emergency_stop multi-symbol live test + e2e live test

**目的**: production 機能の最終実機検証.

実装:
- `executor-server` 起動 → curl で `/v1/exec` (place ETH 0.005)
- 数秒後 curl で `/v1/exec/{id}/cancel`
- emergency_stop 経由の multi-symbol cancel (testnet で別 agent wallet で 2 件 place → emergency_stop で全 cancel)
- e2e: ユーザーが server を立ち上げ, Python connector (`src/executor/client.py`) から HTTP request

これで Phase 3.5 完成判定.

### 4.3 HL 仕様の重要制約 (実機検証で判明)

| 制約 | 値 | 影響 |
|---|---|---|
| min notional | $10 | size cap で考慮必須 |
| price format | 5 sig fig + (6 - szDecimals) decimal max | `best_bid * 0.99` は invalid → **tick グリッドから計算必須** |

| `agent wallet` 署名 | master EOA とは別 | 取引・ポジは master EOA 帰属 |

## 6. 既知の落とし穴 (前回 + このセッション分)

### 6.1 (前回引き継ぎから継続) 主要罠

- `tokio::time::pause()` 中は `tokio::time::Instant` を使う (std だと実時間)
- `cargo` は `cd executor` してから (workspace ルート)
- production code で `unwrap/expect` は clippy fail
- `pyproject.toml` の新 extras は `[all]` に必ず追加
- emergency_stop は cancel-then-abort 順序厳守
- `docs/executor/cli.md` から `tests/...` は `../../`

### 6.2 このセッションで新規発見

#### `rmp_serde::to_vec` ≠ `to_vec_named` (PR-B1)

`rmp_serde::to_vec` は struct を msgpack ARRAY として encode (compact form). 一方 Python `msgpack.packb(dict)` は MAP. HL action_hash は MAP を要求するため **`pack_action()` ヘルパー (= `to_vec_named` ラッパー) を必ず使う**. 直接 `to_vec` 呼ぶと sign が python-sdk と一致しない.

→ `executor-hl/src/eip712.rs::pack_action` 経由が唯一の正解. cross-check fixture で検証済.

#### HL price format の sig-fig 制約 (PR-B2b)

`best_bid * 0.99` の浮動小数点演算が 6 sig fig 以上を出すと HL が `Order has invalid price` で reject. **tick グリッド (`best_bid - n * tick`) から計算すれば valid by construction**.

→ `live_mainnet_place_cancel.rs` で `tick = book.bids[0].px - book.bids[1].px` 観測式を採用.

#### HL min notional $10 (PR-B2b)

PR-B2b で `0.001 ETH * $2380 = $2.38` で reject 経験. 現在 `TARGET_NOTIONAL_USD = $15`, `MIN_NOTIONAL_USD = $10`, `MAX_NOTIONAL_USD = $50` で動的 size 計算.

#### `OrderIntent.asset` field は Leaky Abstraction (PR-C1)

PR-B2a で hot fix として追加した `OrderIntent.asset: u32` は HL 固有 wire detail を domain type に漏らしていた. PR-C1 で削除 + `MetaCache` で `RealHlClient` 内部解決. **algo は asset を意識しない** が原則.

#### `flatten()` の silent shrink (PR-C1)

`Vec<Option<OrderResponse>>.into_iter().flatten().collect()` は None slot を silent に消す → 入力/出力長が不一致になりバグ温床. **`unwrap_response_slots()` で fail-fast** (`HlError::InvalidResponse` 返す).

#### `dyn HlClient: !Sized` (PR-C1)

`spawn_batch_sender<C>(...)` が `C: HlClient + Sized` を要求するため, `Arc<dyn HlClient>` を直接渡せない. **match arm 内で具体型 `Arc<MockHlClient>` / `Arc<RealHlClient>` で spawn → `Arc<dyn HlClient>` に erase** が標準解決. trait object 経由の dispatch が必要なら別途 `impl HlClient for Arc<dyn HlClient>` 提供.
